1"""Public Forecast Benchmark — GridPulse vs. each BA's own day-ahead forecast. 

2 

3The product competes against a *free* incumbent: EIA-930 publishes each 

4balancing authority's own day-ahead forecast (the ``DF`` column). This 

5module scores the two head-to-head, continuously, riding instrumentation 

6that already exists rather than a one-shot replay: 

7 

8* **Official arm** — ``first_seen_df`` from the vintage instrument. 

9* **GridPulse arm** — the resolved 24h/48h snapshots the horizon-drift 

10 pipeline already keeps, settled-regraded (#318). 

11* **Truth** — the vintage ``last_d``, EIA's settled value, used as the 

12 SINGLE truth for both arms so neither is scored against its own yardstick. 

13 

14## Two provenance limits, now measured (``docs/BENCHMARK_PROVENANCE.md``) 

15 

16Both were found by design review after the first implementation. Neither is 

17an open question any more, and what each one still forbids is stated here: 

18 

191. **``first_seen_df`` is not "the day-ahead value as published."** 

20 ``data.vintage`` only admits an hour once EIA publishes a metered ``D``, 

21 so the DF we store was re-read 0–3h *after* the target hour, not at 

22 day-ahead time. **Measured:** EIA does revise DF, very unevenly — 7 of 10 

23 sampled BAs never revise at all (PJM, MISO, ERCOT, CAISO, GVL, SPP, 

24 NYISO), while PSEI revises 26.4% and SOCO 24.2%. The largest movement in 

25 any sampled operator's own *median* APE is 1.43 points — which bounds 

26 nothing about a head-to-head result, since verdicts are decided on *mean* 

27 MAPE and the probe never measures it. So rather than pick a side, the 

28 official arm is scored **both ways** (``official`` as-issued, 

29 ``official_revised`` as EIA's current view) and both verdicts publish. Still forbidden: calling 

30 either one "their day-ahead forecast" — a revision that landed *before* 

31 our first capture is invisible to us, so the phrasing stays "the earliest 

32 day-ahead forecast we observed." 

332. **The lead is measured per tick, not assumed.** 

34 ``_resolve_forecast_start`` anchors the forecast at the last *real* 

35 demand hour, so with EIA's publishing lag a nominal "24h" record carries 

36 a realized ~23.9h. ``jobs.phases._observed_lead_hours`` computes that 

37 from the forecast payload each tick and passes it as ``observed_lead_h``; 

38 the payload publishes the number and sets ``lead_basis`` to ``observed``. 

39 Still forbidden: an unqualified "24 hours ahead" claim — quote the 

40 realized figure, which is the shorter one. 

41 

42## The traps this module does defend against 

43 

441. **The stub trap.** For not-yet-reported hours EIA publishes the official 

45 forecast *as* the actual (``D == DF``). Scoring those hours would credit 

46 the official forecast with a perfect prediction on hours it never made. 

47 Two predicates drop them: the first-sight ``was_placeholder`` flag, and — 

48 the sharper one — any hour whose *settled* value still equals the 

49 day-ahead forecast, where the official arm scores 0% by construction and 

50 our arm is being graded against their forecast rather than reality. 

512. **The preliminary-actuals trap.** First-published actuals run up to 70% 

52 wrong on high-revision feeds. Only settled ``last_d`` is truth. 

53 

54## Exclusions are a feature, not an omission 

55 

56A BA is excluded when it cannot be scored *fairly*, and the reason is 

57published. Two classes: 

58 

59* **broken-feed** — the feed revises so heavily that intraday scoring is 

60 meaningless, AND (ADR-009) GridPulse's own anchor is seeded from that 

61 BA's day-ahead forecast, which would make the comparison partly 

62 self-referential. Saying so is the transparency product. 

63* **df-coverage** — the BA publishes a day-ahead forecast too sparsely to 

64 score (<80% of hours). 

65 

66## Lead-time handling 

67 

68Ours is a *nominal* 24h snapshot, realized ~23.9h (measured every tick — 

69see limit 2 above). Theirs is a day-ahead submission documented at 

70**17–41h** depending on hour-of-day, per the Form EIA-930 instructions — 

71documented, not observed by us. The payload therefore also carries the 

72comparison at our nominal **48h** snapshot, realized ~47.9h, which clears 

73their documented maximum. That arm is *labelled* conservative only while 

74the tick's own observed lead exceeds 41h, so the label lapses by itself if 

75EIA's publishing lag ever grows. 

76"""

191def wape(actual: np.ndarray, predicted: np.ndarray) -> float: 

192 """Weighted absolute percentage error: ``Σ|a−p| / Σ|a| × 100``. 

193 

194 Reported alongside MAPE because MAPE is dominated by small-denominator 

195 hours, which systematically misrepresents small BAs — the ones where 

196 this benchmark's most striking results live. 

197 """ 

198 a = np.asarray(actual, dtype=float) 

199 p = np.asarray(predicted, dtype=float) 

200 denom = float(np.sum(np.abs(a))) 

201 if denom <= 0: 

202 return float("nan") 

203 return float(np.sum(np.abs(a - p)) / denom * 100.0)

206def score_arm(pairs: list[PairedHour], arm: str) -> dict[str, float]: 

207 """MAPE / median APE / MAE / WAPE for one arm over the paired hours. 

208 

209 ``mape`` is the **mean** APE — the industry-standard headline, and the 

210 statistic the winner is decided on. ``median_ape`` is published beside it 

211 because the offline reports (``docs/BENCHMARK_SCOREABILITY.md``, 

212 ``docs/BENCHMARK_PROVENANCE.md``) characterise BAs by *median* APE, and a 

213 reader carrying a figure between artifacts without noticing the statistic 

214 changed would be comparing two different things. On a feed with a fat 

215 error tail the two diverge substantially — which is information, not 

216 noise: a large gap says the BA's error is tail-driven. 

217 """ 

218 actual = np.array([p.actual for p in pairs], dtype=float) 

219 pred = np.array([getattr(p, arm) for p in pairs], dtype=float) 

220 if actual.size == 0: 

221 return { 

222 "mape": float("nan"), 

223 "median_ape": float("nan"), 

224 "mae": float("nan"), 

225 "wape": float("nan"), 

226 "n": 0, 

227 } 

228 ape = np.abs(actual - pred) / actual * 100.0 

229 return { 

230 "mape": round(float(np.mean(ape)), 3), 

231 "median_ape": round(float(np.median(ape)), 3), 

232 "mae": round(float(np.mean(np.abs(actual - pred))), 1), 

233 "wape": round(wape(actual, pred), 3), 

234 "n": int(actual.size), 

235 }

241def _hour(ts: Any) -> datetime | None: 

242 """Parse a vintage timestamp, or None if it does not parse. 

243 

244 Never raises: a single unparseable row must not take down the gate. An 

245 unparseable timestamp is simply not evidence of anything, so it is skipped 

246 rather than defaulted — defaulting it would let one bad row decide whether 

247 a BA is published. 

248 """ 

249 try: 

250 return datetime.fromisoformat(str(ts).replace("Z", "+00:00")) 

251 except (TypeError, ValueError): 

252 return None

255def _df_staleness(vintage_records: list[Any]) -> tuple[float | None, str | None]: 

256 """``(hours since the newest published DF, when that DF's hour was)``. 

257 

258 Measured against the newest record in the window rather than wall-clock, so 

259 the function stays pure and a replay of an old window reports what that 

260 window saw. ``(None, None)`` when the BA published nothing at all, which the 

261 caller treats as maximally stale — a BA with no DF in the window has not 

262 stopped publishing *recently*, it has published nothing. 

263 

264 Takes the max rather than the last element: the callers all pass sorted 

265 records today, but a gate that silently depends on caller-side ordering is 

266 one refactor away from reading a different number. 

267 """ 

268 newest = max((t for r in vintage_records if (t := _hour(r.timestamp))), default=None) 

269 newest_df = max( 

270 (t for r in vintage_records if np.isfinite(r.first_seen_df) and (t := _hour(r.timestamp))), 

271 default=None, 

272 ) 

273 if newest is None or newest_df is None: 

274 return None, None 

275 return (newest - newest_df).total_seconds() / 3600.0, _normalize_ts(newest_df.isoformat())

278def _absent_hour_bias_pct(vintage_records: list[Any]) -> float | None: 

279 """Do the hours a BA skipped carry different load than the hours it published? 

280 

281 ``(mean D on absent hours - mean D on covered hours) / mean D on covered``, 

282 as a percentage. This is the hazard the old coverage gate was a proxy for — 

283 a BA that goes quiet when the grid gets hard would be graded only on its 

284 easy hours. Published, and it gates nothing: promoting it to a gate needs a 

285 disqualifying magnitude, and the fleet has not yet produced one to calibrate 

286 against (#549). 

287 

288 ``None`` when it cannot mean anything: no absent hours (no bias is 

289 *possible* — distinct from unmeasurable), no covered hours, or too few 

290 absent hours for the mean to be stable. Non-finite and non-positive ``D`` 

291 are dropped from **both** sides, so one bad row cannot move it. 

292 

293 ## It is confounded wherever the absence is BLOCKED — which here is always 

294 

295 The statistic compares two sets of hours as though they were drawn from the 

296 same period. That holds when absences are scattered through the window. It 

297 does not hold for a contiguous outage, where the difference also carries 

298 whatever load happened to do during those particular days. 

299 

300 Measured on the live payload 2026-08-18: **WALC −19.88%** over 49 absent 

301 hours, which sit in two contiguous ~48h blocks, and **AVA −17.41%** over 24 

302 hours in one block. A 48h block spans two full diurnal cycles, so neither is 

303 an off-peak artifact — those days were milder, and the BA's choice of hours 

304 had nothing to do with it. 

305 

306 ``MIN_ABSENT_HOURS_FOR_BIAS`` does not address this. It was fitted to drop 

307 3–4-hour cases, and the confound is a property of the absence's **shape**, 

308 not its size. Since no BA in this fleet is diffusely absent (#549), every 

309 value this function returns today carries it to some degree. 

310 

311 So read it as *"were the dark hours different?"* — never as *"does this BA 

312 withhold its forecast on hard hours?"* Those coincide only for scattered 

313 absence. **Separating them is a precondition for promoting this to a gate,** 

314 on top of finding a disqualifying magnitude: a blocked-absence BA could be 

315 excluded for a cold snap it did not choose. 

316 """ 

317 covered = [ 

318 float(r.last_d) 

319 for r in vintage_records 

320 if np.isfinite(r.first_seen_df) and np.isfinite(r.last_d) and r.last_d > 0 

321 ] 

322 absent = [ 

323 float(r.last_d) 

324 for r in vintage_records 

325 if not np.isfinite(r.first_seen_df) and np.isfinite(r.last_d) and r.last_d > 0 

326 ] 

327 if not covered or len(absent) < MIN_ABSENT_HOURS_FOR_BIAS: 

328 return None 

329 mean_covered = float(np.mean(covered)) 

330 if mean_covered <= 0: 

331 return None 

332 return round((float(np.mean(absent)) - mean_covered) / mean_covered * 100.0, 2)

335def scoreability(vintage_records: list[Any], revision_class: str | None) -> dict[str, Any]: 

336 """Can this BA be scored, and if not, exactly why? 

337 

338 Returns ``{"scoreable", "reason", "reason_detail", "df_coverage", 

339 "df_asissued_coverage", "placeholder_pct", "n_hours"}``. The reason travels 

340 with the verdict so every exclusion is publishable. 

341 

342 ## Two coverages, because one number was answering two questions (#535) 

343 

344 * ``df_coverage`` — **the BA's publication rate.** Does this balancing 

345 authority publish a day-ahead forecast at all? A property of the BA, and 

346 the only one this gate is entitled to act on, because the exclusion text 

347 it produces makes a claim about the BA. 

348 * ``df_asissued_coverage`` — **our capture quality.** What share of hours 

349 did we observe the DF for *before the hour settled*, i.e. in time for the 

350 as-issued arm? A property of our collector. Published, never a gate. 

351 

352 Until #535 these were the same number. ``first_seen_df`` was pinned on the 

353 tick that first admitted the hour and never revisited, so a DF that EIA 

354 published slightly later was lost permanently — and the gate read that loss 

355 as sparse publishing. Twenty-six BAs were excluded on it, five of them large 

356 ISOs, on a public page. Measured against EIA directly on 2026-08-17, exactly 

357 one of the excluded set (SPP, 53.8%) is genuinely below the threshold. 

358 

359 ``data.vintage`` now gives the DF a second look, so ``df_coverage`` means 

360 what it says. The capture-quality half did not disappear — it moved to its 

361 own field, where a reader can see it and it decides nothing. 

362 

363 ## Coverage does not gate; feed liveness does (#549) 

364 

365 #535 fixed *what* the coverage number measured. It did not establish that a 

366 publication **rate** is the right thing to exclude on, and it is not: a rate 

367 cannot tell a BA that half-publishes from a BA that published completely and 

368 then stopped, and the exclusion sentence it produced asserted the first 

369 shape for both. 

370 

371 Measured across all 51 BAs on 2026-08-18, the distinction the rate was 

372 assumed to be drawing does not exist in this fleet. **No BA is diffusely 

373 sparse.** Every BA with any absence has 92-100% of its absent hours inside 

374 runs of >=3h. SPP — the one BA the coverage gate ever correctly excluded, 

375 and which this module previously described as genuinely not publishing — is 

376 absent in **one contiguous 341-hour block**: its feed stopped at 

377 ``2026-08-04T06Z`` and did not resume. TEC, at 80.1%, is absent in six 

378 blocks and publishes 100% of hours on the days it publishes at all. Both 

379 were confirmed against EIA directly, so neither is a capture artifact. 

380 

381 What actually separates them is **liveness**, and it separates them 

382 cleanly: hours since the newest published DF were SPP 341, TEC 30, every 

383 other BA <=6. So that is what gates. 

384 

385 The defect in scoring a stopped feed is not thinness — ``MIN_PAIRED_HOURS`` 

386 already owns sample size, and SPP's covered hours are unbiased (+0.18%). 

387 It is that every hour we could score predates the stop, so the row 

388 describes a different slice of the window than every other row, under a 

389 header that says 30 days. That is #535's defect class — a headline 

390 describing a population the reader does not expect — one level up. 

391 

392 ``df_coverage`` follows ``df_asissued_coverage`` into the published-but- 

393 deciding-nothing set, joined by ``absent_hours_bias_pct``: the hazard the 

394 rate was standing in for, now measured directly instead of assumed. 

395 """ 

396 n = len(vintage_records) 

397 if n == 0: 

398 return { 

399 "scoreable": False, 

400 "reason": EXCLUDE_INSUFFICIENT, 

401 "reason_detail": EXCLUSION_REASONS[EXCLUDE_INSUFFICIENT], 

402 "df_coverage": 0.0, 

403 "df_asissued_coverage": 0.0, 

404 "placeholder_pct": 0.0, 

405 "n_hours": 0, 

406 "n_absent_hours": 0, 

407 "df_stale_hours": None, 

408 "df_last_published_at": None, 

409 "absent_hours_bias_pct": None, 

410 } 

411 

412 from data.vintage import FRESH_CAPTURE_LAG_HOURS, df_capture_lag_hours 

413 

414 has_df = sum(1 for r in vintage_records if np.isfinite(r.first_seen_df)) 

415 as_issued = sum( 

416 1 

417 for r in vintage_records 

418 if np.isfinite(r.first_seen_df) 

419 and (lag := df_capture_lag_hours(r)) is not None 

420 and lag <= FRESH_CAPTURE_LAG_HOURS 

421 ) 

422 placeholders = sum(1 for r in vintage_records if r.was_placeholder) 

423 coverage = has_df / n 

424 

425 stale_h, last_df_at = _df_staleness(vintage_records) 

426 

427 reason: str | None = None 

428 if revision_class in UNSCOREABLE_CLASSES: 

429 reason = EXCLUDE_BROKEN_FEED 

430 # A BA that published nothing at all in the window has `stale_h is None`, 

431 # and is excluded here rather than falling through as though its feed were 

432 # fresh — "no DF anywhere" is the strongest possible form of the condition 

433 # this gate tests, not an absence of evidence about it. 

434 elif stale_h is None or stale_h > MAX_DF_STALENESS_HOURS: 

435 reason = EXCLUDE_DF_FEED_STOPPED 

436 

437 return { 

438 "scoreable": reason is None, 

439 "reason": reason, 

440 # The measured figures, not just the rule. A reader who sees only 

441 # "under 80% of hours" cannot tell 79% from 39%, and those are 

442 # different facts about a BA. 

443 "reason_detail": _reason_detail(reason, coverage, as_issued / n, n, last_df_at), 

444 "df_coverage": round(coverage, 4), 

445 "df_asissued_coverage": round(as_issued / n, 4), 

446 "placeholder_pct": round(placeholders / n * 100, 2), 

447 "n_hours": n, 

448 "n_absent_hours": n - has_df, 

449 # The gate's own figure, published whether or not it fired, so a reader 

450 # can see how far from it a scored BA sits instead of taking the 

451 # verdict on trust. 

452 "df_stale_hours": None if stale_h is None else round(stale_h, 1), 

453 "df_last_published_at": last_df_at, 

454 "absent_hours_bias_pct": _absent_hour_bias_pct(vintage_records), 

455 }

458def _reason_detail( 

459 reason: str | None, 

460 coverage: float, 

461 as_issued_coverage: float, 

462 n_hours: int, 

463 last_df_at: str | None = None, 

464) -> str | None: 

465 """The published exclusion rationale, carrying THIS BA's measured numbers. 

466 

467 ``EXCLUSION_REASONS`` states the rule; this states the case. Both DF-side 

468 texts name the as-issued share, because #535 was precisely a reader — us — 

469 unable to tell "the BA barely publishes" from "we barely captured it" from 

470 the sentence that shipped. 

471 

472 The stopped-feed text names **the hour the feed stopped**, which is the 

473 whole point of #549: the sentence that preceded it asserted a *shape* 

474 ("too sparse") that had never been measured and was wrong for both BAs it 

475 was ever applied to. A date is checkable against EIA in one query; a shape 

476 adjective is not. 

477 """ 

478 if reason is None: 

479 return None 

480 base = EXCLUSION_REASONS[reason] 

481 if reason != EXCLUDE_DF_FEED_STOPPED: 

482 return base 

483 if last_df_at is None: 

484 return ( 

485 f"{base} Over the {n_hours}-hour window EIA carried no day-ahead " 

486 "forecast for this BA at all." 

487 ) 

488 return ( 

489 f"{base} Its most recent day-ahead forecast covers {last_df_at}. " 

490 f"Measured over {n_hours} hours: EIA published a day-ahead forecast " 

491 f"for {coverage:.1%} of them, of which we captured " 

492 f"{as_issued_coverage:.1%} in time to score as-issued." 

493 )

496#: An hour is an unresolved stub when settled truth still equals the 

497#: day-ahead forecast to within this many MW. Compared on the 2dp values 

498#: EIA publishes, so the tolerance only absorbs float noise. 

499STUB_EPSILON_MW = 0.01

510 

511 Returns ``(pairs, drop_counts)`` — the per-reason counts are published, 

512 because the exclusions are not neutral across BAs and a reader who cannot 

513 see that will assume the worst. MISO loses ~20% of its hours to stubs and 

514 ~10% more to hours with no published DF; the cleanest feeds still lose a 

515 percent or two. None loses nothing. 

516 

517 Drop reasons, in evaluation order (the order matters: each hour is 

518 attributed to the FIRST rule it trips, so these counts are disjoint): 

519 

520 * ``no_df`` — the BA published no day-ahead forecast for the hour. 

521 Checked first, because both stub predicates read as "not a stub" when 

522 DF is simply absent. 

523 * ``unsettled`` — no finite, positive settled actual yet. 

524 * ``unresolved_stub`` — settled value still equals the day-ahead 

525 forecast. The official arm would score exactly 0% by construction, 

526 *and* our arm would be graded against their forecast rather than 

527 reality. This is the sharper of the two stub predicates. 

528 * ``first_seen_placeholder`` — flagged ``D == DF`` at first sight. 

529 Dropped conservatively even when later corrected. 

530 * ``stale_capture`` — the hour's ``DF`` was first seen more than 

531 ``FRESH_CAPTURE_LAG_HOURS`` after the hour passed, so its ``first_seen_df`` 

532 is a POST-revision value. Measured on ``df_at`` since #535, because a DF 

533 filled on a later tick is exactly the case this rule exists to catch. Putting it on the as-issued arm collapses the 

534 as-issued/as-revised distinction the dual arm exists to draw (#358). 

535 Evaluated right after ``no_df`` because it disqualifies the official 

536 arm's *provenance* — a more fundamental objection than "the settled 

537 value still equals it". That ordering moves some hours out of the stub 

538 buckets and into this one; the counts stay disjoint, but they are not 

539 comparable to payloads published before #358. 

540 * ``no_gridpulse`` — we have no matured prediction for the hour. Both 

541 arms are always scored on the SAME hour set; a one-sided score would 

542 compare a 30-day official record against a 1-day GridPulse one. Note 

543 the cost: the operator's forecast for that hour exists and goes 

544 unscored, so the sample is conditioned on OUR availability too. 

545 """ 

546 out: list[PairedHour] = [] 

547 from data.vintage import FRESH_CAPTURE_LAG_HOURS, df_capture_lag_hours 

548 

549 drops = { 

550 "unresolved_stub": 0, 

551 "first_seen_placeholder": 0, 

552 "unsettled": 0, 

553 "no_df": 0, 

554 "no_gridpulse": 0, 

555 "stale_capture": 0, 

556 } 

557 for r in vintage_records: 

558 official = r.first_seen_df 

559 if not np.isfinite(official): 

560 drops["no_df"] += 1 

561 continue 

562 if exclude_stale_capture: 

563 # THE DF's lag, not the hour's. Since #535 a DF may be filled on a 

564 # tick later than the one that admitted the hour, and it is the DF 

565 # observation that the as-issued claim is about. Reverting this to 

566 # `capture_lag_hours` would silently put post-revision values on the 

567 # as-issued arm at scale — the exact #358/#392 defect, and the one 

568 # way the #535 fix could do more harm than the bug. Pinned by 

569 # TestStaleCapture::test_late_filled_df_cannot_reach_the_asissued_arm. 

570 lag = df_capture_lag_hours(r) 

571 # An unparseable timestamp cannot be shown fresh, and the official 

572 # arm's whole claim is that its value was seen before the hour 

573 # settled — so an unmeasurable lag is treated as stale rather than 

574 # waved through. 

575 if lag is None or lag > FRESH_CAPTURE_LAG_HOURS: 

576 drops["stale_capture"] += 1 

577 continue 

578 actual = r.last_d 

579 if not np.isfinite(actual) or actual <= 0: 

580 drops["unsettled"] += 1 

581 continue 

582 if abs(actual - official) < STUB_EPSILON_MW: 

583 drops["unresolved_stub"] += 1 

584 continue 

585 if r.was_placeholder: 

586 drops["first_seen_placeholder"] += 1 

587 continue 

588 gp = gridpulse_by_ts.get(_normalize_ts(r.timestamp)) 

589 if gp is None or not np.isfinite(gp): 

590 drops["no_gridpulse"] += 1 

591 continue 

592 # Falls back to the as-issued value, so a BA that never revises 

593 # (7 of 10 sampled) scores identically on both arms. 

594 revised = (revised_df_by_ts or {}).get(_normalize_ts(r.timestamp)) 

595 if revised is None or not np.isfinite(revised): 

596 revised = official 

597 out.append( 

598 PairedHour( 

599 timestamp=str(r.timestamp), 

600 actual=float(actual), 

601 official=float(official), 

602 gridpulse=float(gp), 

603 official_revised=float(revised), 

604 ) 

605 ) 

606 return out, drops

609def revised_df_from_frame(demand_df: Any) -> dict[str, float]: 

610 """EIA's CURRENT day-ahead forecast per hour, from the live demand frame. 

611 

612 ``forecast_mw`` on the freshly fetched frame *is* the post-revision DF, 

613 so the conservative official arm needs no new capture — the value is 

614 already in the frame the scoring job holds. 

615 """ 

616 if demand_df is None or getattr(demand_df, "empty", True): 

617 return {} 

618 cols = getattr(demand_df, "columns", []) 

619 if "forecast_mw" not in cols or "timestamp" not in cols: 

620 return {} 

621 out: dict[str, float] = {} 

622 for ts, value in zip(demand_df["timestamp"], demand_df["forecast_mw"], strict=False): 

623 try: 

624 v = float(value) 

625 except (TypeError, ValueError): 

626 continue 

627 if np.isfinite(v): 

628 out[_normalize_ts(pd_ts_iso(ts))] = v 

629 return out

644def gridpulse_predictions( 

645 horizon_payload: dict[str, Any] | None, model: str, lead: str 

646) -> dict[str, float]: 

647 """Extract ``{target_hour: predicted}`` from the horizon-drift payload. 

648 

649 Reads the resolved records the horizon pipeline already keeps for 

650 ``models.{model}.{lead}.records``, and takes **only the prediction** from 

651 them. The drift record's own ``actual`` is deliberately ignored: this 

652 module re-grades every prediction against the vintage ``last_d``, so both 

653 arms are scored by one yardstick computed in one place rather than each 

654 inheriting its own pipeline's notion of truth. 

655 """ 

656 if not horizon_payload: 

657 return {} 

658 block = ((horizon_payload.get("models") or {}).get(model) or {}).get(lead) or {} 

659 out: dict[str, float] = {} 

660 for row in block.get("records") or []: 

661 ts = row.get("ts") or row.get("timestamp") 

662 pred = row.get("p", row.get("predicted")) 

663 if ts is None or pred is None: 

664 continue 

665 try: 

666 out[_normalize_ts(ts)] = float(pred) 

667 except (TypeError, ValueError): 

668 continue 

669 return out

672def serve_grade( 

673 horizon_payload: dict[str, Any] | None, model: str, lead: str 

674) -> dict[str, Any] | None: 

675 """Our own live grade for **the exact series this row scores** (#348). 

676 

677 Read off the same ``models.{model}.{lead}`` block 

678 :func:`gridpulse_predictions` takes its predictions from — deliberately 

679 not a champion-across-models or a different horizon. The marker on the 

680 page must describe the line in that row, not a neighbouring measurement 

681 that happens to be healthier. 

682 

683 Returns ``None`` when the block carries no grade, which is a warming 

684 region, not a passing one. 

685 """ 

686 if not horizon_payload: 

687 return None 

688 block = ((horizon_payload.get("models") or {}).get(model) or {}).get(lead) or {} 

689 grade = block.get("grade") 

690 if not grade: 

691 return None 

692 # The boundary the number had to cross to earn this grade. `mape_grade` 

693 # returns `rollback` for anything ABOVE `acceptable` — the band dict's own 

694 # "rollback" entry (12.0 at 24h) is never used as a threshold, so quoting 

695 # it on the page would overstate how bad a flagged row has to be. 

696 from config import MAPE_BY_HORIZON 

697 

698 bands = MAPE_BY_HORIZON.get(lead) or {} 

699 return { 

700 "grade": grade, 

701 "model": model, 

702 "horizon": lead, 

703 "rolling_mape_7d": block.get("rolling_mape_7d"), 

704 "n_7d": block.get("n_7d"), 

705 "acceptable_max": bands.get("acceptable"), 

706 }

709def _stale_capture_impact( 

710 vintage_records: list[Any], 

711 gridpulse_by_ts: dict[str, float], 

712 revised_df_by_ts: dict[str, float] | None, 

713 gridpulse_now: dict[str, Any], 

714 official_now: dict[str, Any], 

715) -> dict[str, Any] | None: 

716 """How the #358 exclusion moved this BA's published numbers. 

717 

718 Rescoring the same lead WITHOUT the filter is the only honest way to 

719 answer the methodology's §14 requirement continuously: the direction is 

720 not uniform across BAs (it favours the operator where its revisions 

721 improve its forecast and favours us where they worsen it), so a single 

722 fleet statement would be wrong for roughly half the fleet. 

723 

724 ``None`` when nothing was excluded — the common case once a vintage window 

725 has rolled past its seed, and worth distinguishing from "measured zero". 

726 """ 

727 pairs, drops = pair_hours( 

728 vintage_records, gridpulse_by_ts, revised_df_by_ts, exclude_stale_capture=False 

729 ) 

730 n_stale = len(pairs) - int(gridpulse_now.get("n") or 0) 

731 if n_stale <= 0 or len(pairs) < MIN_PAIRED_HOURS: 

732 return None 

733 without = {"gridpulse": score_arm(pairs, "gridpulse"), "official": score_arm(pairs, "official")} 

734 return { 

735 "n_hours_excluded": n_stale, 

736 # Positive = the exclusion IMPROVED that arm's published MAPE. 

737 "gridpulse_mape_shift_pts": round( 

738 float(without["gridpulse"]["mape"] - gridpulse_now["mape"]), 3 

739 ), 

740 "official_mape_shift_pts": round( 

741 float(without["official"]["mape"] - official_now["mape"]), 3 

742 ), 

743 "note": ( 

744 "same hours rescored without the stale-capture filter; positive " 

745 "means the exclusion improved that arm's MAPE" 

746 ), 

747 }

753def compute_benchmark_payload( 

754 region: str, 

755 vintage_records: list[Any], 

756 horizon_payload: dict[str, Any] | None, 

757 revision_class: str | None, 

758 *, 

759 model: str = "ensemble", 

760 mean_revision_pct: float | None = None, 

761 revised_df_by_ts: dict[str, float] | None = None, 

762 observed_lead_h: dict[str, float] | None = None, 

763 served_series: str | None = None, 

764) -> dict[str, Any]: 

765 """Build ``gridpulse:benchmark:{region}`` for one tick. 

766 

767 Always returns a payload — an excluded BA carries its reason rather than 

768 silently vanishing, because the exclusion list is part of what gets 

769 published. 

770 

771 ``revised_df_by_ts`` supplies EIA's current (post-revision) day-ahead 

772 values so the conservative official arm can be scored; ``observed_lead_h`` 

773 carries this tick's measured lead per nominal horizon, which decides 

774 whether the conservative label may be applied at all. 

775 

776 ``served_series`` names what the product actually serves for this BA 

777 (``"model"`` or ``"seasonal-naive"``). It does not change a single score 

778 — this arm always grades ``model``, by design, so the benchmark keeps 

779 measuring the forecaster rather than quietly re-basing onto whatever we 

780 fell back to. But where the two differ the row is no longer describing 

781 what a user of that BA gets, and #348 is precisely about rows that carry 

782 context we hold and do not publish. 

783 """ 

784 score = scoreability(vintage_records, revision_class) 

785 payload: dict[str, Any] = { 

786 "region": region, 

787 "revision_class": revision_class, 

788 "mean_revision_pct": mean_revision_pct, 

789 **score, 

790 "scored_model": model, 

791 "served_series": served_series, 

792 "serves_scored_model": None if served_series is None else served_series == "model", 

793 "leads": {}, 

794 } 

795 if not score["scoreable"]: 

796 return payload 

797 

798 for lead in (HEADLINE_LEAD, CONSERVATIVE_LEAD): 

799 gridpulse_by_ts_for_lead = gridpulse_predictions(horizon_payload, model, lead) 

800 pairs, drops = pair_hours( 

801 vintage_records, 

802 gridpulse_by_ts_for_lead, 

803 revised_df_by_ts, 

804 ) 

805 if len(pairs) < MIN_PAIRED_HOURS: 

806 payload["leads"][lead] = { 

807 "scoreable": False, 

808 "reason": EXCLUDE_INSUFFICIENT, 

809 "n": len(pairs), 

810 "excluded_hours": drops, 

811 } 

812 continue 

813 official = score_arm(pairs, "official") 

814 official_revised = score_arm(pairs, "official_revised") 

815 gridpulse = score_arm(pairs, "gridpulse") 

816 

817 observed = (observed_lead_h or {}).get(lead) 

818 block = { 

819 "scoreable": True, 

820 "n": len(pairs), 

821 "official": official, 

822 # EIA revises DF for some BAs, so the conservative arm grades 

823 # them on the value that carries hindsight. Identical to 

824 # `official` wherever the BA never revises. 

825 "official_revised": official_revised, 

826 "gridpulse": gridpulse, 

827 # Positive delta = GridPulse is more accurate on that metric. 

828 "delta_mape": round(official["mape"] - gridpulse["mape"], 3), 

829 "delta_wape": round(official["wape"] - gridpulse["wape"], 3), 

830 # The winner is decided on mean MAPE; this is published so a 

831 # reader can see immediately whether that call is metric- 

832 # dependent, instead of having to take the headline on trust. 

833 "delta_median_ape": round(official["median_ape"] - gridpulse["median_ape"], 3), 

834 "delta_mape_vs_revised": round(official_revised["mape"] - gridpulse["mape"], 3), 

835 "winner": "gridpulse" if gridpulse["mape"] < official["mape"] else "official", 

836 "winner_vs_revised": ( 

837 "gridpulse" if gridpulse["mape"] < official_revised["mape"] else "official" 

838 ), 

839 "excluded_hours": drops, 

840 "observed_lead_h": None if observed is None else round(observed, 2), 

841 "lead_basis": "observed" if observed is not None else "nominal", 

842 # #358 §14: methodology requires stating which direction a rule 

843 # change moves our own number. Rather than predict it, or measure 

844 # it once and let it rot, the payload carries it — the same hours 

845 # rescored WITHOUT the stale-capture filter, so the delta is 

846 # published per BA, per tick, and stays true as windows roll. 

847 "stale_capture_impact": _stale_capture_impact( 

848 vintage_records, gridpulse_by_ts_for_lead, revised_df_by_ts, gridpulse, official 

849 ), 

850 # #348: our own rolling grade for THIS row's series. A row we 

851 # already grade `rollback` was being published as an ordinary 

852 # comparison — the one unflattering fact on the page that wasn't 

853 # disclosed deliberately. 

854 "serve_grade": serve_grade(horizon_payload, model, lead), 

855 } 

856 # The conservative label is EARNED, not assumed: it holds only while 

857 # our realized lead exceeds the operators' documented maximum. 

858 if lead == CONSERVATIVE_LEAD: 

859 block["conservative"] = bool( 

860 observed is not None and observed > OFFICIAL_DOCUMENTED_LEAD_H[1] 

861 ) 

862 block["conservative_basis"] = ( 

863 f"observed lead {observed:.2f}h > documented official max " 

864 f"{OFFICIAL_DOCUMENTED_LEAD_H[1]:.0f}h" 

865 if block["conservative"] 

866 else "withheld — observed lead does not exceed the documented official maximum" 

867 ) 

868 payload["leads"][lead] = block 

869 

870 headline = payload["leads"].get(HEADLINE_LEAD) or {} 

871 payload["scoreable"] = bool(headline.get("scoreable")) 

872 if not payload["scoreable"] and payload.get("reason") is None: 

873 payload["reason"] = EXCLUDE_INSUFFICIENT 

874 payload["reason_detail"] = EXCLUSION_REASONS[EXCLUDE_INSUFFICIENT] 

875 return payload

878def fleet_rollup( 

879 region_payloads: list[dict[str, Any]], *, isolate: tuple[str, ...] = ("ERCOT",) 

880) -> dict[str, Any]: 

881 """Aggregate per-BA results into the fleet headline. 

882 

883 ``isolate`` regions are reported separately rather than folded into the 

884 aggregate (ERCOT by epic requirement — its official forecast is the 

885 fleet's best at ~1.2% and the trader story there rests on quantiles, 

886 not the point scorecard). 

887 """ 

888 scored = [p for p in region_payloads if p.get("scoreable")] 

889 excluded = [p for p in region_payloads if not p.get("scoreable")] 

890 fleet = [p for p in scored if p["region"] not in isolate] 

891 

892 def _headline(p: dict[str, Any]) -> dict[str, Any]: 

893 return p["leads"][HEADLINE_LEAD] 

894 

895 wins = sum(1 for p in fleet if _headline(p)["winner"] == "gridpulse") 

896 gp_mapes = [_headline(p)["gridpulse"]["mape"] for p in fleet] 

897 off_mapes = [_headline(p)["official"]["mape"] for p in fleet] 

898 

899 return { 

900 "n_scoreable": len(scored), 

901 "n_excluded": len(excluded), 

902 "excluded": [{"region": p["region"], "reason": p.get("reason")} for p in excluded], 

903 "fleet": { 

904 "n": len(fleet), 

905 "wins": wins, 

906 "losses": len(fleet) - wins, 

907 "median_gridpulse_mape": round(float(np.median(gp_mapes)), 3) if gp_mapes else None, 

908 "median_official_mape": round(float(np.median(off_mapes)), 3) if off_mapes else None, 

909 # The consistency story: our spread vs theirs, both on MEAN 

910 # MAPE. Note the 41x figure quoted elsewhere is a *median* APE 

911 # spread from docs/BENCHMARK_SCOREABILITY.md — a different 

912 # statistic over a different hour set, not this field. 

913 "gridpulse_spread": _spread(gp_mapes), 

914 "official_spread": _spread(off_mapes), 

915 }, 

916 "isolated": {p["region"]: _headline(p) for p in scored if p["region"] in isolate}, 

917 }

920def _spread(values: list[float]) -> dict[str, float] | None: 

921 if not values: 

922 return None 

923 lo, hi = float(min(values)), float(max(values)) 

924 return { 

925 "min": round(lo, 3), 

926 "max": round(hi, 3), 

927 "ratio": round(hi / lo, 1) if lo > 0 else None, 

928 }

934def scoreability_alerts( 

935 rollup: dict[str, Any], 

936 region_payloads: list[dict[str, Any]], 

937 *, 

938 min_scoreable: int | None = None, 

939 coverage_warn: float | None = None, 

940) -> list[dict[str, Any]]: 

941 """Alertable events when the scorecard's population is shrinking (#535). 

942 

943 Pure: returns ``[{"event", **fields}]`` for the caller to log. The scoring 

944 job owns the I/O; the rule lives here beside the gate it watches, and is 

945 unit-testable without Redis. 

946 

947 ## Why these events and not a threshold on the count we already log 

948 

949 ``benchmark_fleet_written`` has carried ``scoreable``/``excluded`` since 

950 E0, and a metric-threshold alert on it is the obvious design and a trap — 

951 the same one ``docs/monitoring/backtest_recompute_alert.json`` documents. 

952 It would have to be a **threshold-BELOW** condition, so when the benchmark 

953 phase stops emitting entirely the logs-based counter has *no data*, the 

954 condition never evaluates, and the alert goes quiet at precisely the moment 

955 it should fire. 

956 

957 Both events below therefore fire on the **failing** direction and increase 

958 as things get worse, so absence of data can never mask them. A benchmark 

959 phase that stops running is a different failure, already covered by 

960 ``cloud_run_job_failure_alert`` and ``scoring_partial_failure``. 

961 

962 ## Two distances from the same cliff 

963 

964 * ``benchmark_scoreability_drop`` — the fleet count is below the floor. 

965 The incident itself: #535 published 25 of 51 for three weeks. 

966 * ``benchmark_coverage_at_risk`` — a BA is still scoreable but its 

967 ``df_coverage`` sits in the warning band **above** the gate. By the time 

968 a BA falls out, the public page is already wrong; this names it first. 

969 First real firing 2026-08-18T06:18Z: TEC at 80.1%, a tenth of a point 

970 above the 0.80 gate, with ``df_asissued_coverage`` 49.0%. Checked 

971 against EIA over the same 719-hour window — 576 DF hours published, 576 

972 recorded — so the gap was TEC's, not ours. (The band was first argued 

973 from CAISO 82.9% / PJM 81.0%; those were the broken pre-fix numbers and 

974 now read 100.0% / 99.7%.) 

975 

976 ``df_asissued_coverage`` is deliberately NOT alerted on. It measures our 

977 capture, not the BA's publishing, and gating on it is the whole of #535. 

978 It rides along on the payload so an on-call reader can tell the two apart. 

979 

980 ## Since #549 this event watches a number that no longer gates 

981 

982 Coverage stopped deciding the population; ``MAX_DF_STALENESS_HOURS`` does. 

983 ``benchmark_coverage_at_risk`` is kept because a BA's publishing rate 

984 degrading is still worth a look, but it is now purely informational — its 

985 original "by the time a BA falls out the page is already wrong" argument 

986 belongs to a gate it no longer guards. ``df_stale_hours`` rides on the 

987 entry so an on-call reader sees the distance to the **real** gate rather 

988 than inferring it from a rate. 

989 

990 **Stated rather than left implicit: nothing watches the staleness gate 

991 itself yet (#587).** ``benchmark_scoreability_drop`` cannot cover it — its 

992 floor is 40 against a ceiling of 46, so six BAs must die before it fires 

993 and one dying feed never trips it. What does warn today is an accident: 

994 a dead feed's coverage crosses the 0.85 band after ~108h of the 719-hour 

995 window, ~60h before this gate, so the ordering holds only while those two 

996 unrelated constants keep their present values — and it is already 

997 saturated for a BA like TEC that sits below the band regardless. 

998 """ 

999 from config import BENCHMARK_DF_COVERAGE_WARN, BENCHMARK_MIN_SCOREABLE 

1000 

1001 floor = BENCHMARK_MIN_SCOREABLE if min_scoreable is None else min_scoreable 

1002 warn = BENCHMARK_DF_COVERAGE_WARN if coverage_warn is None else coverage_warn 

1003 

1004 out: list[dict[str, Any]] = [] 

1005 n_scoreable = rollup.get("n_scoreable") 

1006 if isinstance(n_scoreable, int) and n_scoreable < floor: 

1007 out.append( 

1008 { 

1009 "event": "benchmark_scoreability_drop", 

1010 "n_scoreable": n_scoreable, 

1011 "n_excluded": rollup.get("n_excluded"), 

1012 "floor": floor, 

1013 # WHICH BAs, not just how many — "26 excluded" and "26 excluded 

1014 # including five large ISOs" are different pages. 

1015 "excluded_regions": sorted( 

1016 str(e.get("region")) for e in (rollup.get("excluded") or []) 

1017 ), 

1018 } 

1019 ) 

1020 

1021 for p in region_payloads: 

1022 if not p.get("scoreable"): 

1023 continue 

1024 cov = p.get("df_coverage") 

1025 if not isinstance(cov, int | float) or cov >= warn: 

1026 continue 

1027 out.append( 

1028 { 

1029 "event": "benchmark_coverage_at_risk", 

1030 "region": p.get("region"), 

1031 "df_coverage": round(float(cov), 4), 

1032 "df_asissued_coverage": p.get("df_asissued_coverage"), 

1033 "warn_below": warn, 

1034 # The real gate since #549, and the distance to it. `gate` used 

1035 # to be MIN_DF_COVERAGE, which no longer decides anything. 

1036 "df_stale_hours": p.get("df_stale_hours"), 

1037 "gate_stale_hours": MAX_DF_STALENESS_HOURS, 

1038 } 

1039 ) 

1040 return out
